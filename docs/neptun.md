# Neptun profile and ELTE portal notes

Neptun is deployed differently across institutions. [ELTE publishes a portal login](https://neptun.elte.hu/Account/Login), [BGE publishes a student page under a different host and path](https://neptun1.uni-bge.hu/hallgato/Login.aspx), and [BME publishes another student URL](https://me.bme.hu/golyaknak). [BGE documents required MFA](https://uni-bge.hu/en/neptun-ketfaktoros-hitelesites). Those pages establish that host, login page, and MFA policy differ. They do not establish a universal Neptun JSON API.

The bundled `elte-portal` flow preserves the existing ELTE implementation: portal form, optional TOTP form, hand off to a numbered student host, GUID exchange at `Account/OuterLogin`, cached bearer token, and one token refresh with a rotated cookie. The two private HAR files shipped only in the local working folder were inspected in this session without exposing credentials. They show `POST /api/Account/OuterLogin` returning 200 on two numbered student hosts. The portal form details, refresh shape, and endpoint list come from older private observations in this repository and were not independently verified against a current public vendor document in this session. Treat them as ELTE specific and subject to change.

The profile carries `portal_url`, `api_url`, `lcid`, `student_host_suffix`, `flow`, and named relative paths in `[neptun.endpoints]`. The API and portal URLs must use HTTPS. `flow = "unsupported"` prevents login before reading credentials; use a tested provider for another deployment. Copying ELTE endpoint names into another institution's profile is not verification. [A community MobileService.msc description](https://github.com/GreGamingHUN/Neptun-API) documents a different Neptun protocol and must not be treated as proof that these endpoints are generic.

The account lockout and calendar export guards are described in [safety.md](safety.md). `elte --json neptun probe` sends no credential and checks only whether configured paths appear reachable. A 200 response is not proof that the response shape or permission matches this client. A profile must be checked against institution documentation and sanitized offline fixtures before its flow is enabled.
